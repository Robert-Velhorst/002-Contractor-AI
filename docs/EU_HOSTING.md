# EU Hosting Path

Contractor.AI runs locally by default with SQLite and a local evidence directory. The Docker image is portable so the same build can run in an EU-region container platform.

The current schema head is migration `097_durable_evidence_storage_reservations`. It adds shared transactional quota locks and durable upload reservations so concurrent hosted replicas cannot exceed retained evidence quota; lease ownership and cleanup state allow orphan recovery after process restarts. Migration `096_loading_read_indexes` adds two job-scoped resource indexes that preserve business records and reduce loading-list read work. Each hosted company requires its own database, explicit `CONTRACTOR_AI_COMPANY_ID`, and private `companies/<company-id>/` object scope. See [company environment boundaries](COMPANY_ENVIRONMENTS.md), including restore and legacy offline-data limitations. Hosted migration also retains each trusted principal's locale preference and privacy lifecycle. Work-board modules are packaged, but the work board and public registration are independently disabled by default in production. Set `CONTRACTOR_AI_WORK_BOARD_ENABLED=true` only to activate worker access; public account creation additionally requires `CONTRACTOR_AI_WORK_BOARD_REGISTRATION_ENABLED=true`. See [WORK_BOARD.md](WORK_BOARD.md) for the remaining public-launch requirements; local container tests do not establish live hosted acceptance.

Hosted mode is intentionally fail-closed. Set `CONTRACTOR_AI_RUNTIME_MODE=hosted` only after the deployment provides an HTTPS `CONTRACTOR_AI_PUBLIC_URL`, a strong `CONTRACTOR_AI_AUTH_TOKEN`, an EU S3-compatible evidence store, and a reachable managed PostgreSQL target in `CONTRACTOR_AI_DATABASE_URL`. The database URL must authenticate the server certificate and hostname with `sslmode=verify-full` and the provider trust chain. At startup the ledger applies schema creation, versioned migrations, and legacy seeding under a PostgreSQL advisory lock; concurrent replicas wait on the same database connection boundary instead of applying a migration twice. A failed or timed-out startup closes that connection so the lock cannot survive the failed process. Hosted mode never falls back to a local SQLite file.

The selected Hetzner profile uses the Falkenstein Object Storage endpoint `https://fsn1.your-objectstorage.com` and region `fsn1`. Hetzner documents that Object Storage has no default encryption at rest and supports customer-provided SSE-C encryption. Hosted startup therefore requires `CONTRACTOR_AI_S3_SSE_C_KEY`: a canonical base64 encoding of a random 32-byte key (generate with `openssl rand -base64 32`). The same key is sent with signed S3 PUT/GET requests and must be preserved in an independent, access-controlled recovery location; losing it makes encrypted evidence unrecoverable. Do not replace this key in place: key rotation for already-stored objects is not implemented, and historical evidence would become unreadable. SSE-C does not encrypt object metadata. Create a private bucket, enable bucket versioning, and verify lifecycle/retention behavior before migration. See Hetzner's [Object Storage security FAQ](https://docs.hetzner.com/storage/object-storage/faq/general/), [SSE-C guide](https://docs.hetzner.com/storage/object-storage/howto-protect-objects/encrypt-with-sse-c/), and [versioning guide](https://docs.hetzner.com/storage/object-storage/howto-protect-objects/protect-versioning/). Bucket use is billable; the deployment guide does not create or purchase a bucket.

Production readiness also requires `CONTRACTOR_AI_HOSTING_PROVIDER`, `CONTRACTOR_AI_HOSTING_REGION`, `CONTRACTOR_AI_DATA_RESIDENCY=EU`, a retained `CONTRACTOR_AI_DPA_REFERENCE`, and a retained `CONTRACTOR_AI_RETENTION_POLICY_REFERENCE`. These fields are operator declarations, not provider attestations; preserve the referenced contract, retention schedule, and residency evidence outside the application. `CORS_ORIGINS` must include the exact public HTTPS origin.

Set `CONTRACTOR_AI_TRUST_PROXY` to the exact ingress source IP, CIDR range, or an intentionally selected Express subnet name visible to the container. Hosted startup fails without it. Boolean trust, numeric hop counts, wildcards, and universal CIDRs are rejected because path-length changes or a direct connection could otherwise let a caller spoof `X-Forwarded-For` and bypass per-client controls. Keep the application port loopback-bound, restrict container-network membership, and verify the observed ingress source after every proxy or network change. General API limits are atomically retained in SQLite or PostgreSQL so restarts and additional replicas do not grant a fresh quota. `CONTRACTOR_AI_RATE_BUCKET_LIMIT` bounds table cardinality: source addresses are HMAC-assigned to that fixed bucket space and are never stored directly. The minimal health probe remains available while a client bucket is limited.

Operators sign in through the application with an unpadded, non-template role access key containing at least 32 characters. Contractor.AI exchanges the key for a signed HTTP-only, `SameSite=Strict`, `Secure` cookie and does not retain the key in browser storage. A one-way session id hash is retained in PostgreSQL, allowing logout to revoke the cookie across restarts and replicas. Cookie-authenticated writes require an `Origin` that matches the request host or the explicit CORS allowlist, closing cross-site form submission paths. `CONTRACTOR_AI_SESSION_TTL_SECONDS` is bounded between 15 minutes and 24 hours; the default is eight hours. Failed sign-ins use a separate fixed-window limiter controlled by `CONTRACTOR_AI_LOGIN_RATE_LIMIT`, `CONTRACTOR_AI_LOGIN_RATE_WINDOW_MS`, and `CONTRACTOR_AI_LOGIN_RATE_BUCKET_LIMIT`. Its HMAC bucket and atomic count are retained in the ledger, making the limit restart-persistent, replica-safe, and cardinality-bounded without storing the client address; successful authentication clears prior failures. Restore and local-to-hosted migration deliberately clear old login and API limiter rows so one environment's transient quota state is not copied into another. Rotate the underlying owner or role token to invalidate all sessions after suspected disclosure. API clients may continue to use bearer or API-key headers instead of a browser session.

Every retained audit event advances one SHA-256 chain head in the same SQLite or PostgreSQL transaction as the underlying change. PostgreSQL writers lock that one head row, so concurrent replicas cannot create two valid successors. `/api/readiness`, `/api/operations/capabilities`, and owner-only `/api/operations/audit-integrity` verify the retained sequence, event payload hashes, and head. A mismatch fails readiness; recover from a known-good provider recovery point instead of rewriting or silently re-chaining production history.

The evidence storage adapter uses the standard S3 API with `CONTRACTOR_AI_S3_ENDPOINT`, `CONTRACTOR_AI_S3_BUCKET`, `CONTRACTOR_AI_S3_REGION`, `CONTRACTOR_AI_S3_ACCESS_KEY_ID`, and `CONTRACTOR_AI_S3_SECRET_ACCESS_KEY`. Hosted endpoints must use HTTPS and cannot contain embedded credentials, query parameters, or fragments. Configure a private bucket, EU residency, encryption at rest, and the provider's DPA before use. Every retained reference is constrained to `CONTRACTOR_AI_S3_PREFIX`, preventing a ledger record from reading a sibling tenant prefix. Evidence is served through the authenticated ledger route, never from a public object URL.

The runtime role needs object read/write/delete access within the configured prefix, bucket-level `s3:ListBucketVersions` scoped to that prefix, and `s3:DeleteObjectVersion` for that prefix. Startup verification exercises version listing and cleanup as well as bounded PUT/GET. Orphan cleanup lists all versions and delete markers for the exact unreferenced object key before deleting them; incomplete pagination, more than 1,000 versions, retention locks, or denied permissions leave the reservation pending for operator recovery. The application does not purge versions of retained ledger evidence.

Hosted startup performs bounded PUT/GET and exact-version cleanup verification against a unique readiness marker under `CONTRACTOR_AI_S3_PREFIX`. The service does not listen when the bucket is unreachable, credentials are rejected, the marker cannot be read back, or the marker versions cannot be removed. `CONTRACTOR_AI_STORAGE_TIMEOUT_MS` bounds each object-store request and `CONTRACTOR_AI_STORAGE_VERIFY_TTL_MS` controls the verification cache. Grant the runtime only the object and version permissions it needs for the configured prefix. Docker probes the minimal public `/api/health/ready` endpoint; detailed runtime and provider state remains behind authenticated `/api/readiness` and `/api/operations/capabilities` routes.

Evidence retry receipts are stored in the same PostgreSQL ledger as the document record. Keep the application and database clocks synchronized: active upload leases prevent concurrent duplicate work, every processing attempt has a unique owner token, and stale attempts cannot complete or release a reclaimed receipt. Completed receipts replay exact retries for 24 hours without writing a second object. Reusing a key for a changed payload fails closed.

The optional autonomous scheduler also coordinates through PostgreSQL. Every due-cycle claim is an atomic compare-and-swap against the lease state the replica observed, and completion is accepted only from the current lease owner. Concurrent replicas may all poll, but only one can run a due cycle; a stale worker cannot overwrite the current owner's outcome. Cycles remain ledger-only and idempotent, and record zero external commitments.

Migration `068_operational_safety_controls` retains the owner-controlled autonomous-work state, reason, actor, revision, and audit history. Suspended state blocks scheduled claims and applied command plans across replicas, but permits dry-run diagnosis and direct operator records. Set `CONTRACTOR_AI_RELEASE_SHA` to the deployed Git revision so owner diagnostics identify the exact build. Neither control can stop physical equipment or replace the site's emergency and Stop Work Authority procedures.

For a controlled hosted staging run, copy `.env.hosted.example` to the non-committed `.env.hosted`, replace every placeholder, then run `docker compose --env-file .env.hosted -f docker-compose.hosted.yml up --build`. The explicit `--env-file` is required for Compose interpolation. Hosted Compose deliberately does not provision a database: point it at the same class of managed EU PostgreSQL service used in production, with encrypted connections, backups, point-in-time recovery, and a signed DPA. The Compose port binds to loopback only; place an EU-hosted HTTPS ingress on the same host in front of it and set `CONTRACTOR_AI_TRUST_PROXY` to that ingress connection's observed source. The container filesystem is read-only, Linux capabilities are dropped, and privilege escalation is disabled.

Declare recovery with `CONTRACTOR_AI_POSTGRES_BACKUP_MODE=snapshot` or `pitr`, `CONTRACTOR_AI_OBJECT_VERSIONING_ENABLED=true`, and a retained `CONTRACTOR_AI_BACKUP_POLICY_REFERENCE`. Readiness fails until all three are present. Exercise the referenced database restore and evidence-version recovery before production use and after material provider-policy changes.

Application-local backup endpoints intentionally return `409 provider_recovery_required` in hosted mode. The application cannot safely claim to have backed up provider-managed PostgreSQL and S3 data by writing files inside its container. The operational export remains available as a human-readable reconciliation artifact, but it is not a recovery image.

The local-first workflow uses SQLite. Hosted workflow uses PostgreSQL through the same ledger interface. Do not expose a local data volume publicly or treat an ephemeral serverless filesystem as operational storage.

Run `npm run test:container` before publishing an image. The release gate builds the actual multi-stage Dockerfile and exercises its production process with authentication enabled, a read-only root filesystem, a bounded temporary filesystem, all Linux capabilities dropped, privilege escalation disabled, loopback-only port publishing, and a dedicated durable volume. It verifies public and authenticated readiness, non-root execution, Docker health, clean signal handling, and retained sessions across a container restart. CI requires this executable gate in addition to inspecting the Compose declaration. Docker excludes every `.env*` file from its build context so deployment credentials cannot be captured in an image layer.

Before a hosted migration, create `/api/operations/backup`, validate its restore readiness through `/api/operations/restore/validate`, verify its signed v3 manifest includes the expected evidence count and a valid audit chain, download the verified `tar.gz` package from `/api/operations/backups/:backupId/download`, and download `/api/operations/export`. Verify the export through `/api/operations/exports/validate`, then store both artifacts on encrypted off-device media according to the operator's retention policy. The export is a reconciliation record, not a recovery image. Signed local v3 packages authenticate and checksum both SQLite and private evidence; they are not a substitute for managed PostgreSQL snapshots or hosted object-store versioning.

Follow [Company Handover](COMPANY_HANDOVER.md) to freeze the stopped source and seal a fresh package to the target's independent environment key. Keep the hosted application stopped. Point `CONTRACTOR_AI_DATABASE_URL` at a new, empty managed PostgreSQL database, configure the private S3-compatible variables and the target authority key, and run with those private variables already loaded:

```powershell
npm run migrate:hosted -- --backup-id <backup-id> --permit-file <permit.json> --receipt-output <verified.json> --confirm MIGRATE_<backup-id>
```

The migration accepts an authenticated backup manifest v3, not the summary JSON export. It requires the matching backup signing key and PostgreSQL TLS, takes an exclusive migration lock, refuses any target containing operational rows, copies durable business tables in foreign-key order, uploads every evidence file and reads each object back before committing. Browser/OIDC sessions are invalidated. Evidence references are rewritten for hosted storage. The target remains staged and cannot start until its verified receipt is released by the retired source. Failure definitely before the commit attempt rolls back rows and attempts uploaded-object cleanup; a lost commit acknowledgment retains both data and evidence for investigation. Historical unsigned compatibility in the library is not a substitute for the canonical CLI's targeted handover permit.

# Completion-review migration note

Migration `092_client_completion_review` retains source-hash-bound client statements against a current, delivered handover dossier. The current ledger head is `097_durable_evidence_storage_reservations`; older schema heads in dated evidence remain historical. PostgreSQL contract tests require a dedicated disposable loopback server and `CONTRACTOR_AI_POSTGRES_TEST_URL` pointing to `contractor_ai_test` or a `contractor_ai_test_<suffix>` database. See the README verification section for the safety boundary. Passing those tests is local adapter evidence, not proof of live EU hosting, provider recovery, object-store durability or an operator-approved production deployment.
